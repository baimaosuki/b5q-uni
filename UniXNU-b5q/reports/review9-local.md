## Physical evidence and changes

- Bluetooth: review8 L774/805 and review8-2 L938/948 show UART14 INTID493 and zero IRQ counts. `GeniI2c.c` and the GENI register definitions select CPU M/S routing with SE_IRQ_EN bits2/3. FIFO start now writes the named `F_SE_CPU_IRQS=0xc`, replacing DMA IRQ bits0/1. Start, W1C service, quiesce, failure and resume are checked with a causal hardware IRQ model. An unsolicited HCI event must wake the worker when retry_at=0 without any timer. The same model demonstrates that the old mask3 cannot wake it.
- Bluetooth power lifecycle: `worker()` is the single executor of powerOn/off; `requestPower()` only CAS-queues a request. `powerOn()` returns immediately when already powered. Proactive startup and a queued tty power request can produce two success acknowledgements without executing two physical resets/downloads. Keep both tty notifications. `log-bluetooth=2` prints health every5s including SE_IRQ_EN, IRQ, tty power/open/speed and discovery/RX counters. `qbt_tty.c`/`qbt_transport_power_result()` retain their lock-protected pending/wakeup protocol and30s limit.
- Wi-Fi: review8-2 L991/993 and L1288 show zero6GHz rule allocation failure and missing regulatory data before cmd36866/20493 timeouts. Board allocate(0) now allocates only its16B size header and returns a non-null aligned pointer; release subtracts the same header and frees the exact original size. Overflow and OOM still fail. The real generated WMI regulatory parser is exercised with zero and one rules under ASan/UBSan.
- Wi-Fi generated kernel adapter: only WCN6855_HW21 with single MSI disables hw_params.idle_ps before mac_start can send IDLE_PS_CONFIG=1. The upstream single-MSI branch already keeps ASPM disabled because MHI M2 register reads can hang. Other hardware and multi MSI keep their policy. Missing default_regd fails add_interface with EAGAIN before vdev/WMM effects. WMI timeout diagnostics report the actual endpoint credits, idle_ps and multi-MSI state. Shared IRQ routing, HTC credit accounting and shadow/wake algorithms are unchanged. The pinned core calls hif_start before HTC setup and pdev registration, so this idle_ps guard is in effect before mac_start. Pinned MHI runtime_get/put are no-ops; pcic retains its existing bus wake/release around BAR accesses beyond the always-on window. These source checks identify the remaining unqualified wake boundary without claiming that a missing interrupt was measured.
- USB: roleThread uses100ms sampling when detached,50ms for a valid VCONN-only candidate, and1s for stable attached or an invalid bus. Source fallback requires valid CC pin1/2, VCONN, no water and PD DFP bit7. VCONN diagnostics use the CCCTRL1 value read back at DRP init instead of issuing a synchronous opcode that could block500ms and consume the Source window; immediate status bytes and a control-cached marker remain logged. Initial Source DP discovery is likewise deferred until BC reports VBUS, so optional DP mailbox work cannot precede OTG power; existing active DP links retain their original path. Candidate and native Source use the same effective cable signature, so enabling local VBUS/BC feedback does not tear down Host. Existing a1/b1 Device, powered Sink+DFP hub and real unplug behavior remain covered. The original exhaustive131072-case role test retains all combinations and adds the specifically requested VCONN/DFP case to its expectation.
